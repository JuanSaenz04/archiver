# AGENTS.md

Agent instructions for `github.com/JuanSaenz04/archiver`.

## Architecture overview

Two Go binaries backed by Redis Streams + SQLite + a React/Vite frontend embedded in the API binary:

- `cmd/api` — Echo HTTP server, serves REST + embedded frontend
- `cmd/worker` — blocks on Redis Streams, shells out to browsertrix-crawler (Docker only)
- `internal/api` — handlers; embeds `dist/` via `//go:embed dist`
- `internal/store` — SQLite via pure-Go `modernc.org/sqlite` (no CGo)
- `internal/queue` — Redis Streams producer + consumer
- `internal/crawler` — shells out `xvfb-run node /app/dist/main.js crawl ...`
- `front/` — React 19, TanStack Router (file-based), shadcn/ui, TailwindCSS 4, pnpm

## Critical: `internal/api/dist/` must exist before building or testing

`routes.go` uses `//go:embed dist`. If the directory is absent, **all** Go builds and `go test ./...` fail.

- Production: `cd front && pnpm build`, then copy `front/dist/` to `internal/api/dist/`
- CI / quick local: `mkdir -p internal/api/dist && touch internal/api/dist/placeholder.txt`

## Developer commands

### Go backend
```bash
go test -v ./...                          # run all tests
go test -v ./internal/store/...           # single package
go build -o api.out ./cmd/api             # build API
go build -o worker.out ./cmd/worker
```

No Makefile. `start_api.sh` and `start_worker.sh` are convenience build+run scripts.

### Frontend (`front/`)
```bash
pnpm dev      # Vite dev server; proxies /api → localhost:1080
pnpm build    # tsc -b && vite build → dist/
pnpm lint     # ESLint (flat config, *.ts/*.tsx only)
```

Package manager is **pnpm** (not npm/yarn).

## Testing notes

- `internal/store` tests use in-memory SQLite (`file:<uuid>?mode=memory&cache=shared`) — no setup needed.
- `internal/api` tests use `miniredis` (in-memory Redis) and `httptest` — no services needed, but `internal/api/dist/` must exist.
- `internal/archiveutil` tests are pure unit tests.
- Worker (`internal/crawler`) requires the browsertrix-crawler Docker image and is not unit-tested.

## Code generation

- `front/src/routeTree.gen.ts` is auto-generated by the TanStack Router Vite plugin on every `pnpm dev` or `pnpm build`. **Never edit it manually.**
- Adding a frontend page = create a file under `front/src/routes/`; the router picks it up automatically.

## SQLite migrations

Managed in-app via `PRAGMA user_version` in `internal/store/store.go`. No external migration tool. `RunMigrations()` runs at startup for both binaries. Add new migrations there following the existing v1→v2 pattern.

## Docker

- `Api.Dockerfile`: multi-stage (node build → go build → distroless scratch). Copies `front/dist/` into `internal/api/dist/` before `go build`.
- `Worker.Dockerfile`: layered on `webrecorder/browsertrix-crawler`. The worker is not usable outside Docker.
- `docker-compose.yml` is gitignored; use `docker-compose.example.yml` as the template.

## CI (`.github/workflows/go.yml`)

Runs on push/PR to `main`. Steps: checkout → setup-go (stable) → create placeholder `dist/` → `go mod download` → `go test -v ./...`. No lint step in CI.

## Archive viewer design

The WACZ viewer is intentionally isolated using a two-layer approach:

1. **`replaywebpage` assets are self-hosted.** `front/public/replay/ui.js` and `sw.js` are copied from `node_modules/replaywebpage/` and committed under `front/public/replay/`. They are served at `/replay/` to avoid any external CDN dependency. To update them: `cp node_modules/replaywebpage/sw.js public/replay/sw.js && cp node_modules/replaywebpage/ui.js public/replay/ui.js` (run from `front/`).

2. **`viewer.html` is a standalone page served at `/viewer.html`.** It loads `/replay/ui.js`, mounts a `<replay-web-page>` custom element, and reads the `?source=` query param to point the player at a `.wacz` file URL. The `replayBase="/replay/"` attribute tells the element where to find `sw.js`, which registers a service worker scoped to `/replay/` — everything under that path is intercepted by the SW to serve archived content.

3. **The React app embeds `viewer.html` in an `<iframe>` (`front/src/components/archive-viewer.tsx`).** The iframe isolation is deliberate: `replaywebpage` injects global CSS and sets up its own service worker scope. Running it inside the main React document would pollute the app's global styles and potentially conflict with the app's own routing. The `key={viewerUrl}` prop forces a full iframe remount when the selected archive changes.

Do not attempt to render `<replay-web-page>` directly inside the React component tree — the global style injection and service worker scope are the reasons the iframe boundary exists.

## Conventions

- File + DB consistency is maintained at the handler layer, not via cross-store transactions. Delete/rename handlers move files to a temp location, update the DB, then remove the temp; they roll back the file move on DB failure.
- `SyncFromDisk()` runs at API startup using `INSERT OR IGNORE` — it only adds untracked `.wacz` files, never overwrites metadata.
- `NormalizeArchiveName` in `internal/archiveutil` strips path traversal (`filepath.Base`), replaces spaces with `-`, and appends `.wacz` if missing. Always pass user-provided names through it.
- `GEMINI.md` (gitignored) contains additional AI agent notes and is present on disk but not in git history.
